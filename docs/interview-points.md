# Interview points

Talking points this repo is designed to support.

## The one-liner

"An operations copilot for hospital patient flow: it answers bed, boarding,
discharge, and staffing questions over governed data, matches ED boarders to
beds with a transparent acuity-weighted score, and gates discharge overrides
behind human confirmation -- all audit-logged."

## Architecture decisions worth defending

- **Views + gateway instead of raw SQL:** the planner can only SELECT from
  four allowlisted views; denials cite stable rule IDs (SEC-SELECT-01, SEC-WRITE-02, SEC-VIEW-03), and a SQLite authorizer
  enforces the allowlist however a table is spelled (ADR 0001).
  Least privilege for data access.
- **Transparent scoring over black-box ranking:** the bed matcher returns its
  breakdown (acuity fit / capability / headroom) because a bed manager must
  defend the assignment.
- **Checklist gates, not vibes:** discharge-ready is a boolean over five
  named items; overrides need a human, a reason, and an audit entry.
- **Clinical refusal as a guardrail:** the planner refuses clinical questions
  outright -- operational scope is a safety boundary, not a missing feature.

## Failure modes I can discuss

- Stale bed state (a "free" bed that isn't) -- treated as a data-quality
  incident in the SOP; the matcher can only be as good as the bed board.
- No eligible bed for a boarder -- escalated with a reason, never silently
  dropped.
- Demand feed down -- explicit gap result; the planner answers from internal
  telemetry alone rather than hallucinating demand.
